# Changelog

All notable changes to Saathi are documented here. Format loosely follows
[Keep a Changelog](https://keepachangelog.com/). Newest entries at the top.

## [Unreleased]

### Added
- **Admins now get an email when a new report is submitted.** New `src/lib/email.ts` — a minimal Resend wrapper with one function so far, `notifyAdminOfNewReport()`. Wired into `reportPost`/`reportComment` immediately after `prisma.report.create()` succeeds, so no email fires on the unauthenticated, duplicate-report (silent dedupe), or rate-limited paths. Email is intentionally minimal: report type, content ID, reason, timestamp, and a link to `/admin` — no reporter identity, no full post/comment content. Awaited (not fire-and-forget) so a serverless runtime can't terminate the function before the send completes, but `notifyAdminOfNewReport()` internally catches every failure (missing config, network error, Resend API error) and only logs — it never throws, so a broken/unconfigured mailer can never block or roll back a report. Added `EMAIL_FROM` to `.env.example`, defaulting to Resend's built-in `onboarding@resend.dev` test sender if unset, which works with zero domain setup but only delivers to the Resend account's own address until a real domain is verified.

### Fixed
- **Report submission now rate-limited (10/day per user).** `reportPost`/`reportComment` previously had no cap on distinct reports across different posts/comments — a bad actor could flood the moderation queue. Added a shared `hasReachedDailyReportLimit()` helper (scoped to `reports.ts`, used by both functions) mirroring the exact daily-count pattern already used in `createPost` (3/day) and `createComment` (10/day): count today's reports for the user, block at the limit, same `>=` boundary semantics. Limit chosen to match the existing comment limit as a reasoned anchor rather than a new guess, extracted into a single `DAILY_REPORT_LIMIT` constant. `ReportButton.tsx` needed no changes — it already correctly displays `{ error }` responses. Purely additive to `reports.ts` (25 insertions, 0 deletions) — `resolveReport`/`getPendingReports` untouched.
- **Admins can no longer suspend their own account.** `suspendUser()` had no guard against an admin targeting themselves, with no un-suspend UI anywhere in the codebase to recover from it. Added a check comparing the acting admin's own DB id against the target id, returning `{ error: "You cannot suspend your own account." }` instead of performing the update. Also fixed `AdminTabs.tsx`'s `handleSuspend`, which previously ignored `suspendUser`'s return value entirely and would show a false "User suspended." success toast even when the server rejected the request — it now checks the result and shows a distinct error-styled toast (extending the existing toast component with a `type` field, defaulting to `"success"` for the three other unmodified call sites).
- **`/create` now pre-selects a category from the URL.** `category/[slug]/page.tsx`'s "Share your story" link has always pointed to `/create?category=<id>`, but the create page never read that param — users arriving from a category page landed on a blank category picker. `useSearchParams()` now initializes the selected category, validated against the real `CATEGORIES` list so an unknown or hand-typed value safely falls back to no selection instead of a broken state. Required wrapping the form in a `<Suspense>` boundary per the App Router's requirement for `useSearchParams()` — the default-exported `CreatePage` component is now a thin Suspense wrapper around the unchanged form logic (moved into `CreatePageForm`), with no visual or behavioral change to the form itself.
- **Content blocklist now actually filters content.** `containsBlockedContent()` previously checked against a two-word placeholder array (`["slur1", "slur2"]`) and blocked nothing in production. It now uses `obscenity`, a maintained profanity/slur-detection library with word-boundary matching and evasion handling (leetspeak, character repetition), wired in via a new `src/lib/blocklist.ts` module. `posts.ts` and `comments.ts` required no changes — the exported function signature from `src/lib/utils.ts` is unchanged.
